# LiveMap — интерактивная карта России с публичными камерами

## Идея проекта

Создать масштабируемую интерактивную карту России, на которой размещены объекты с доступными видеокамерами. Пользователь перемещается по карте, приближает нужный регион, выбирает объект — например, улицу, перекрёсток, площадь, парк, вокзал или другое публичное место — и смотрит камеры, привязанные к нему.

В проекте используются только бесплатные публичные трансляции, тестовые камеры либо потоки, на использование которых есть разрешение. Приватные камеры, платные сервисы и обход ограничений доступа не входят в задачу.

## Что должно уметь приложение

- Показывать карту России с возможностью приближения, отдаления и перемещения.
- Отображать на карте объекты, у которых есть одна или несколько камер.
- Объединять большое количество маркеров в кластеры на малом масштабе.
- Загружать объекты только для видимой области карты (`bounding box`).
- Открывать карточку выбранного объекта: название, адрес, координаты и камеры.
- Показывать список доступных камер выбранного места.
- Воспроизводить видеопоток выбранной камеры прямо в браузере.
- Позволять администратору добавлять и редактировать объекты и камеры через API.

## Пользовательский сценарий

1. Пользователь открывает карту России.
2. На общем масштабе он видит кластеры камер и объектов.
3. При приближении появляются отдельные точки: улицы, перекрёстки, площади и другие места.
4. Пользователь нажимает на интересующий объект.
5. Открывается карточка объекта со списком доступных камер.
6. Пользователь выбирает камеру.
7. В модальном окне или боковой панели запускается трансляция.

| --- | --- | --- |

| Запуск сервисов | Docker Compose | Локальный запуск frontend, API, БД и медиа-сервера. |

## Данные и география

Координаты объектов хранятся в PostGIS в системе WGS 84 (`SRID 4326`). Объект — это точка на карте, к которой привязана одна или несколько камер.

```text
locations
├── id: UUID
├── name: string                 # Например: «Перекрёсток Ленина и Мира»
├── type: enum (street, intersection, square, park, station, other)
├── address: string
├── location: geometry(Point, 4326)
├── created_at: datetime
└── updated_at: datetime

cameras
├── id: UUID
├── location_id: UUID → locations.id
├── name: string
├── source_type: enum (hls, webrtc, rtsp)
├── source_url: string           # Исходный URL, если требуется проксирование
├── public_stream_url: string    # URL, который получает браузер
├── status: enum (online, offline, unknown)
└── created_at: datetime
```

Полезные PostGIS-запросы:

- Объекты в текущей области карты: `ST_MakeEnvelope` и `ST_Within` либо оператор `&&`.
- Объекты в заданном радиусе: `ST_DWithin` с типом `geography`.
- Быстрый поиск по карте: GiST-индекс для поля `location`.

## API

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/v1/locations?west=&south=&east=&north=` | Объекты с камерами в текущей области карты в GeoJSON. |
| `GET` | `/api/v1/locations/{id}` | Карточка выбранного объекта. |
| `GET` | `/api/v1/locations/{id}/cameras` | Список камер выбранного места. |
| `GET` | `/api/v1/cameras/{id}/stream` | Ссылка для воспроизведения доступного потока. |
| `POST/PATCH/DELETE` | `/api/v1/locations` | Управление объектами. |
| `POST/PATCH/DELETE` | `/api/v1/cameras` | Управление камерами. |

Пример объекта, который frontend получает для карты:

```json
{
  "type": "Feature",
  "id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "geometry": { "type": "Point", "coordinates": [37.6173, 55.7558] },
  "properties": {
    "name": "Перекрёсток в центре Москвы",
    "type": "intersection",
    "camera_count": 2
  }
}
```

## Работа с видеопотоками

Браузеры не воспроизводят RTSP напрямую. Если открытая камера доступна только через RTSP, медиа-сервер получает её поток и отдаёт браузеру HLS или WebRTC:

```text
RTSP-камера → go2rtc / MediaMTX → HLS (.m3u8) или WebRTC → браузер
```

- **HLS** проще подключить через `hls.js`, но задержка обычно выше.
- **WebRTC** даёт меньшую задержку, но требует более сложной настройки.
- Если источник уже публикует бесплатный HLS-поток, его можно воспроизводить без преобразования.
- Использовать следует только открытые потоки, тестовые ссылки или камеры с явным разрешением владельца.

## MVP-план

1. Поднять PostgreSQL с PostGIS через Docker Compose.
2. Создать FastAPI и модели `locations`, `cameras`.
3. Добавить несколько тестовых объектов по России и бесплатные разрешённые тестовые HLS-потоки.
4. Реализовать выдачу объектов в пределах `bounding box`.
5. Добавить Leaflet-карту России с маркерами и кластеризацией.
6. Сделать карточку объекта и список камер.
7. Подключить HLS-плеер в модальном окне.
8. При необходимости настроить go2rtc или MediaMTX для RTSP-источников.
9. Добавить административный доступ для управления данными и проверку статуса камер.

## Развитие проекта

- Фильтры по региону, типу места и статусу камеры.
- Поиск по названию, адресу и городу.
- WebSocket-обновления статусов камер в реальном времени.
- Redis для кэширования запросов карты.
- Фоновая проверка доступности потоков.
- Скриншот последнего кадра и отметка времени последнего обновления камеры.

## Безопасность и законность

- Добавлять только публичные камеры, тестовые потоки или камеры с разрешением правообладателя.
- Не публиковать приватные RTSP-ссылки, учётные данные и внутренние адреса камер.
- Не обходить авторизацию, платный доступ, технические ограничения или условия использования сторонних сервисов.
- Валидировать все URL, координаты и входные данные API.
- Ограничить административное API аутентификацией и ролями.

## Результат

Итоговый проект — удобная карта России для просмотра легально доступных камер: пользователь выбирает объект на карте и сразу открывает связанные с ним трансляции. FastAPI отвечает за API, PostGIS — за быстрые геозапросы, медиа-сервер — за доставку RTSP в браузер, а frontend — за карту и просмотр видео.
