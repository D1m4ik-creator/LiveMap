# LiveMap API v1

Рабочая спецификация OpenAPI доступна на `/openapi.json`, интерактивная форма — на `/docs`. Все маршруты используют префикс `/api/v1`, JSON и координаты WGS84 в порядке `[longitude, latitude]`. Фронтенд карты и будущая админка используют этот же контракт.

## Публичный каталог

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET | `/places?bbox=west,south,east,north&zoom=10` | Точки при `zoom >= 9`, кластеры при меньшем масштабе. |
| GET | `/places/search?q=Москва&limit=10` | Подсказки по опубликованному каталогу: города, адреса, места. |
| GET | `/places/{id}` | Карточка опубликованного места и опубликованные камеры. |
| POST | `/cameras/{id}/reports` | Жалоба на права, приватность, условия или недоступность камеры. |

На карте показываются только места с опубликованной камерой со статусом `online`, свежей проверкой за последние 15 минут, действующим разрешением и пригодным для браузера HTTPS-источником. Неизвестные и недоступные потоки в маркеры не попадают. Карточка опубликованного места может показать опубликованную камеру со статусом `offline` или `unknown`, чтобы объяснить недоступность; `playback_url` тогда `null`. RTSP и источники с секретом не выдаются браузеру до появления медиашлюза.

`bbox` может пересекать 180-й меридиан: `170,40,-170,70`. Координаты должны лежать в допустимых диапазонах, юг должен быть ниже севера. Для `zoom >= 9` ширина и высота области ограничены 20 градусами. Ответ ограничен 500 точками или кластерами и содержит `truncated`.

Пример ответа `GET /places?bbox=37,55,38,56&zoom=10`:

```json
{
  "mode": "points",
  "points": [{"id": 1, "slug": "moscow-square", "name": "Красная площадь", "city": "Москва", "category": "square", "coordinates": [37.6208, 55.7539], "camera_count": 1}],
  "clusters": [],
  "truncated": false
}
```

При `zoom < 9` массив `points` пуст, а `clusters` содержит `id`, центр, число мест и камер. Поиск ограничен 20 результатами, строкой 2–80 символов и 30 запросами в минуту на IP в одном процессе. Он ищет только в опубликованном каталоге с доступными камерами. Геокодирование всех адресов России будет добавлено на фронтенде через лицензированного поставщика карты.

## Администрирование

Первого администратора создают локальной командой `uv run livemap-admin create-user USERNAME --role admin`; пароль вводится интерактивно и хранится только как PBKDF2-хеш. `POST /admin/login` с JSON `{"username":"...","password":"..."}` возвращает Bearer-токен на 8 часов. `POST /admin/logout` отзывает текущую сессию. Токены хранятся в БД только как SHA-256-хеши. Создавать пользователей, одобрять источники, менять статус/публикацию и удалять записи может только роль `admin`; `editor` может создавать и исправлять черновики.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET/POST | `/admin/places`, `/admin/sources`, `/admin/cameras` | Список и создание черновика. |
| GET/PATCH/DELETE | `/admin/places/{id}`, `/admin/sources/{id}`, `/admin/cameras/{id}` | Чтение, изменение, удаление. |
| GET | `/admin/audit` | Журнал изменений без паролей и токенов. |
| GET | `/admin/cameras/{id}/checks` | История результатов проверок без URL и секретов. |
| GET/PATCH | `/admin/reports`, `/admin/reports/{id}` | Очередь обращений и решение, при необходимости со снятием камеры. |
| POST | `/admin/import/preview`, `/admin/import/apply` | Проверка и атомарное применение CSV/GeoJSON. |

Пример последовательности публикации: создать место → создать источник с владельцем, URL, атрибуцией, основанием разрешения, датой проверки и контактом для удаления → создать камеру → администратор одобряет источник → публикует камеру и место → worker проверяет поток. Для iframe требуется точный `embed_host` и ручное `embed_verified_at`; проверка iframe по сети не доказывает, что видео действительно воспроизводится. При смене URL или условий одобрение сбрасывается. RTSP нельзя опубликовать без медиашлюза.

Пример создания места:

```json
{
  "slug": "moscow-square",
  "name": "Красная площадь",
  "address": "Красная площадь",
  "city": "Москва",
  "region": "Москва",
  "category": "square",
  "coordinates": [37.6208, 55.7539]
}
```

URL источника обязан иметь публичный домен и не содержать логин или пароль. Страница источника и браузерный поток используют HTTPS. Публичный HLS-поток не может содержать query-параметры: такие ссылки и источники с `secret_ref` потребуют медиашлюз. Для iframe Ivideon допустимы только известные публичные параметры плеера; произвольные query-параметры блокируются. Секретное значение хранится вне каталога; внутренние сведения о разрешении не выдаются публичным API. Worker проверяет DNS-адреса перед соединением, запрещает локальные сети и редиректы, ограничивает время и размер ответа. Для HLS проверяется CORS манифеста и сегмента. Подробнее — в [эксплуатации камер](camera-operations.md).

## Импорт

Запрос: `{"format":"geojson","content":"<содержимое GeoJSON>"}` или аналогично для `csv`. GeoJSON должен быть `FeatureCollection` с точками и полями места в `properties`; пример: [`demo/places.geojson`](../demo/places.geojson). CSV требует столбцы `slug,name,city,region,category,longitude,latitude`, необязателен `address`. Для создания черновика камеры в той же строке добавляют `camera_name,playback_type,owner_name,public_page_url,stream_url,attribution,permission_note` и при необходимости `secret_ref,permission_expires_at,removal_contact`. Предпросмотр не меняет БД, показывает `create/update` и ошибки по строкам. Применение отказывает при любой ошибке; совпадения по slug обновляются. Максимум 1000 строк и 2 МБ содержимого. Импорт не публикует камеры и не устанавливает фиктивный статус `online`.

## Ошибки

Ошибка имеет вид `{"error":{"code":"place_not_found","message":"Place not found"}}`. `400` означает невалидную область, URL или импорт; `401/403` — отсутствие доступа; `404` — отсутствующую или скрытую запись; `409` — конфликт slug либо нарушение условий публикации; `422` — невалидное тело или параметр; `429` — превышение лимита поиска.
