# LiveMap: архитектура первой версии

Статус: этапы 1–4 реализованы для локального прототипа. Работают карта MapLibre, каталог, плеер и админ-интерфейс. MapTiler проверен с реальным ключом; публичный production-релиз и медиашлюз остаются отдельными этапами. Опубликованы три проверенных эфира; новосибирский источник не разрешает встраивание на сайте LiveMap.

## Компоненты

```text
Браузер (React, TypeScript, MapLibre, плеер HLS/iframe)
  ├─ карта → OpenFreeMap; при настроенном ключе MapTiler Cloud
  ├─ геокодирование вне каталога → MapTiler Cloud (при наличии ключа)
  ├─ метаданные мест/камер → FastAPI /api/v1
  └─ видео → разрешённый источник или отдельный медиашлюз
                              │
FastAPI → сервисы → репозитории → PostgreSQL/PostGIS
                              ↑
              worker проверки доступности камер
```

Фронтенд отвечает за состояние карты, поиск, карточку места и плеер. FastAPI отдаёт метаданные, проверяет доступ и исполняет административные операции. PostgreSQL/PostGIS хранит точки и статусы. Worker отдельно проверяет доступность источников с таймаутами и сетевыми ограничениями. FastAPI не должен становиться универсальным видеопрокси.

## Контракты и границы модулей

- Публичный API под `/api/v1`: выборка по `bbox` и масштабу, детальная карточка места, камеры, поиск. Геометрия в WGS84; наружу координаты идут как `[longitude, latitude]`.
- Административный API: аутентификация, управление местами и камерами, черновики, публикация, импорт и аудит.
- Ошибки API имеют вид `{"error":{"code":"...","message":"..."}}`. В первом этапе уже работают `GET /api/v1/health/live` и `GET /api/v1/health/ready`.
- `api/` переводит HTTP в операции; `services/` содержит сценарии и правила; `repositories/` формирует пространственные запросы к БД; `db/` содержит ORM. Alembic содержит первую миграцию. Форматы опубликованы в [контракте API](api.md).
- При переходе видимой области через 180-й меридиан запрос разбивается на две области; выборка и кластеры ограничены по объёму. Это важно для востока России.

## Карта: принятое решение

Рендерер — **MapLibre GL JS**. По умолчанию используется OpenFreeMap: проверка MapTiler Streets в Москве показала англоязычные подписи на крупном масштабе, поэтому этот стиль не включён в качестве подложки России. При `VITE_MAPTILER_KEY` MapTiler Cloud используется для геокодирования с `language=ru` и `country=ru`; поиск опубликованных мест продолжает работать через собственный API. Проверены запросы Москвы, Казани, Якутска, Владивостока и Новой Ладоги: геокодер вернул результаты с русскими названиями для всех пяти точек. `VITE_MAP_STYLE_URL` позволяет явно задать совместимый пользовательский стиль.

URL стиля и ключ задаются конфигурацией фронтенда; код карты не зависит от одного поставщика. Проверены атрибуция MapTiler/OpenStreetMap в тестовом стиле и отображение атрибуции OpenFreeMap. Решение по тарифу: MapTiler Free допустим только для тестового или личного некоммерческого использования; его квоты — 5 тыс. сессий карты, 1 тыс. поисковых сессий и 100 тыс. API-запросов в месяц. При исчерпании квоты бесплатный сервис приостанавливается до следующего месяца. Для коммерческого использования нужен как минимум Flex ($30/месяц плюс сверхлимитное использование); его spending limit следует выставить в кабинете до включения MapTiler. Фактический расход аккаунта из локальной конфигурации проверить нельзя: статистика доступна только владельцу в Analytics. Сейчас MapTiler используется лишь для геокодера, а подложка — OpenFreeMap. У OpenFreeMap нет SLA и сервис предоставляется «как есть», поэтому перед production с требованиями доступности нужно выбрать платного поставщика или собственный хостинг. Запросы браузера к поставщикам карт идут напрямую; проксирование и массовое скачивание тайлов не планируются.

Основания: [MapLibre](https://maplibre.org/maplibre-gl-js/docs/), [MapTiler API](https://docs.maptiler.com/cloud/api/reference/), [тарифы](https://www.maptiler.com/cloud/pricing/), [условия MapTiler](https://www.maptiler.com/terms/cloud/), [политика тайлов OSM](https://operations.osmfoundation.org/policies/tiles/).

## Live-видео: принятое решение

1. **HLS** — основной формат для браузерного плеера. Используем hls.js там, где работает Media Source Extensions, и нативный HLS при доступности. Проверяем HTTPS, CORS манифеста и сегментов, кодек, задержку и условия источника.
2. **Iframe** — отдельный тип камеры, только если владелец разрешил встраивание. Разрешённые домены фиксируются в каталоге; произвольный HTML не принимается.
3. **RTSP и несовместимые форматы** — браузер напрямую не поддерживает. План отдельного ограниченного [медиашлюза](media-gateway.md) описывает путь через MediaMTX; до развёртывания таких потоков публикация запрещена.

Статус `online/offline/unknown` — результат последней проверки worker, а не гарантия, что поток прямо сейчас воспроизведётся. Плеер всегда обрабатывает обрыв и предоставляет ссылку на первоисточник, когда встраивание недоступно. Целевая задержка для сторонних потоков заранее не обещается: она зависит от источника и способа доставки.

Основание: [hls.js и требования CORS](https://github.com/video-dev/hls.js).

## Состояние реализации

В репозитории есть PostGIS-каталог, административный API и React-интерфейс с картой, карточкой места, плеером и админкой. Отдельный worker ведёт историю проверок и обращений. Интеграционные тесты поднимают временную БД, применяют миграции, проверяют откат и API. Развёрнутый медиашлюз и выбор production-поставщика карт остаются следующими задачами.
