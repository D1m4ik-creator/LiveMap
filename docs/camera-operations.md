# Камеры: проверка, воспроизведение и снятие с публикации

## Каталог кандидатов и права

`demo/camera_candidates.json` содержит 18 записей. На публичном демостенде 30.09.2026 опубликованы 15 камер в 14 местах восьми регионов, три записи остаются черновиками. [Полная проверка десяти черновиков](camera-review-2026-09-30.md) содержит результаты и ограничения геопривязки. `uv run livemap-seed-candidates` добавляет отсутствующие записи как неопубликованные черновики после миграции. `uv run livemap-seed-verified` публикует только прежние восемь заранее проверенных iframe при свежей ручной проверке; новые камеры на другом домене одобряются отдельно.

Одобрение источника требует HTTPS-ссылку на основание разрешения, дату ручной проверки и контакт для удаления. Для iframe также нужен точный `embed_host`, совпадающий с host URL плеера. Изменение владельца, URL, условий, доказательства, даты проверки или хоста сбрасывает одобрение. Публичный API не отдаёт внутренние заметки о правах. Источник без одобрения и опубликованной камеры не появляется на карте.

## Воспроизведение

Для проверки черновика выберите сохранённую камеру и нажмите «Проверить трансляцию». Запустите плеер, убедитесь в живых кадрах и воспроизведении. Только после этого укажите фактическое время встраивания для iframe, одобрите источник и опубликуйте камеру и место. Предпросмотр сам не меняет состояние каталога.

В админке поле «Когда условия проверены» означает дату проверки, а «Срок разрешения» — дату окончания разрешения. Последнее необязательно: оставьте его пустым, если срок окончания не установлен. Если указанная дата уже прошла, одобрение блокируется с сообщением `permission_expired`; отсутствие URL потока даёт отдельное сообщение `missing_stream`. Админка перечисляет недостающие поля и требует сначала сохранить изменения, затем отдельно одобрить источник.

- HLS: `frontend/src/player/CameraPlayer.tsx` использует hls.js при поддержке MSE, нативный HLS как запасной вариант. Есть состояния подключения, обрыва и повтора. При закрытии удаляется media source, видео останавливается. Браузер запрашивает поток непосредственно у владельца или у выделенного медиашлюза.
- Iframe: используется отдельная ветка компонента и только точный домен `embed_host` из одобренного источника. Произвольный HTML не принимается. Встраивание должно быть разрешено владельцем; `X-Frame-Options`/`frame-ancestors` проверяются worker. Администратор подтверждает работу iframe через `embed_verified_at` в течение последних семи дней. Блокировку отдельных политик браузера нельзя гарантированно определить из родительского окна, поэтому всегда остаётся ссылка на страницу владельца.
- RTSP: не выдаётся публичному браузеру. Создание черновика возможно, публикация без шлюза запрещена.

## Worker и статус

Запуск: `uv run livemap-worker` отдельным процессом или `uv run livemap-worker --once` для одного обхода очереди. Интервал проверок задаётся `CAMERA_CHECK_INTERVAL_SECONDS` (минимум 60 секунд), конкурентность `CAMERA_CHECK_CONCURRENCY` (максимум 16). `PUBLIC_ORIGIN` — точный origin браузерного приложения: он нужен для проверки CORS HLS и доменных ограничений RUTUBE. В БД `next_check_at` выполняет роль временной аренды; `FOR UPDATE SKIP LOCKED` не даёт двум worker одновременно забрать одну камеру. Потерянная проверка повторится после срока аренды.

Проверка HLS читает ограниченный размер манифеста, первый вариант и начало первого сегмента. Для **каждого** ответа нужны HTTPS и `Access-Control-Allow-Origin: *` или точное значение `PUBLIC_ORIGIN`. Редиректы, HLS URL с параметрами и приватные/локальные адреса DNS запрещены. Для iframe допускаются только известные публичные параметры Ivideon (`camera`, `server`, `lang`, `width`, `height`); остальные query-параметры блокируются. DNS-ответы проверяются непосредственно в резолвере HTTP-клиента и закрепляются за соединением; прокси из окружения отключены. Установлены таймауты соединения, чтения и всей проверки. Код результата и время сохраняются в `camera_checks`, URL и секреты туда не попадают. Эти проверки подтверждают доступность, но не гарантируют поддерживаемый видеокодек или непрерывную работу потока.

`online` выставляется после успешной проверки; `offline` — после ошибки; `unknown` — если iframe ждёт ручного подтверждения или формат требует шлюза. Для RUTUBE worker дополнительно проверяет официальный API с `Referer` публичного origin: эфир должен быть доступен для встраивания на сайте LiveMap и содержать live HLS. Запрос без `Referer` может ошибочно считать эфир доступным, когда RUTUBE запрещает его на стороннем сайте. Публичная карта требует свежую проверку за последние 15 минут. У опубликованного места карточка объясняет `offline/unknown` и не раскрывает URL воспроизведения. После 12 неудач и отсутствия успеха в течение суток камера автоматически снимается с публикации. Истёкшее разрешение, отозванное одобрение и срок камеры снимают её с публикации при следующем обходе. В обоих случаях добавляется `audit_event`.

## Шлюз для RTSP и подписанных URL

Планируемый отдельный компонент — MediaMTX в приватной сети, с фиксированными путями только для источников, которые прошли ручное одобрение. Конфигурацию путей формирует оператор из allowlist; публичного API для добавления произвольного RTSP URL нет. Секреты и временные URL находятся в secret store, в БД хранится лишь `secret_ref`. На входе шлюза разрешены только заранее согласованные адреса и протоколы; egress ограничивается сетевыми правилами. На выходе HTTPS reverse proxy отдаёт HLS/WebRTC только по опубликованным путям, с TLS, ограничением соединений и требуемым CORS. FastAPI передаёт только метаданные, не проксирует сегменты.

Параметры запуска шлюза для первой оценки: максимум 4 одновременных upstream, 20 зрителей на поток, 2 vCPU/2 ГБ RAM на узел, включение источника по запросу и остановка после 60 секунд без зрителей. Это **бюджет для нагрузочного теста**, не измеренная ёмкость. Перед эксплуатацией необходимо проверить задержку, кодек, стоимость трафика и условия каждого владельца. Пока шлюз не развернут, `rtsp`, `secret_ref` и подписанные URL блокируются правилами публикации.

Основания: [MediaMTX configuration](https://mediamtx.org/docs/references/configuration-file), [MediaMTX HLS](https://mediamtx.org/docs/read/hls), [hls.js](https://github.com/video-dev/hls.js), [CSP frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).

## Жалобы и удаление

Публичный `POST /api/v1/cameras/{id}/reports` принимает обращение о правах, приватности, изменённых условиях, неисправности или другое, не более трёх в час на IP одного процесса. Администратор просматривает `GET /api/v1/admin/reports` и фиксирует решение через `PATCH /api/v1/admin/reports/{id}`; он может одновременно снять камеру с публикации. Для срочного требования владельца сначала вручную выставляется `is_published=false`, затем разбирается обращение. История решений остаётся в `camera_reports` и `audit_events`. Политика эксплуатации: проверять очередь ежедневно, срочные обращения о приватности и правах обрабатывать до следующего публичного показа, пересматривать условия каждого источника при их изменении и до истечения разрешения.
