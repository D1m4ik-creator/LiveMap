## Поиск второго города · 27 сентября 2026

На [странице городских камер «АльянсТелеком»](https://inetvl.ru/dlya-biznesa/alyansglaz/) опубликованы адреса, координаты и iframe для Владивостока (Золотой мост), Уссурийска (Садовая, 3а) и Находки (Пирогова, 16). Три работающих источника сохранены в реестре и локальной БД **только как неопубликованные кандидаты**.

[Описание услуги оператора](https://inetvl.ru/dlya-biznesa/videonablyudenie/) предлагает владельцам встраивать *свои* камеры. Это не подтверждает право LiveMap встраивать перечисленные камеры. Кроме того, iframe на тестовой странице `http://localhost:5173` остались пустыми, хотя их собственные страницы воспроизводились. Нужно получить разрешение оператора и проверить воспроизведение именно на домене LiveMap до публикации. Даты браузерной проверки для этих кандидатов не записаны в `embed_verified_at`, чтобы автоматический импорт не счёл её подтверждением работоспособности на LiveMap.

Повторная проверка эфиров LIVEPOINTS [Москва-река](https://rutube.ru/live/video/849eda0a248516e770a6172f10a14308/) и [Сочи, канатная дорога](https://rutube.ru/live/video/49324935661e2c9527b171c8370e9995/) дала `http_error` от API RUTUBE с `Referer` LiveMap, как и эфир Новосибирска. Публичная страница или отметка `broadcast` в поиске RUTUBE не снимает ограничение автора на стороннем сайте.

[Live World Webcams](https://liveworldwebcams.com/embed-webcam/) предлагает свободно вставляемый виджет и [показывает 14 камер России](https://liveworldwebcams.com/category/asia/russia/). Однако его [публичный код виджета](https://liveworldwebcams.com/wp-content/plugins/lww-embed-widget/assets/widget.js) выводит миниатюру с переходом `Watch Live` на сайт источника, а не живое видео в карточке. Поэтому виджет не закрывает требование C01 и не добавлен в каталог как live-плеер.

[smotriomsk.ru](https://smotriomsk.ru/cam13.htm) указывает точное место камеры на улице Ленина, 5 и встраивает VK Video. 27.09 на странице проекта после запуска плеера появился текущий кадр 856×480 (`readyState=4`, воспроизведение не приостановлено). [Правила проекта](https://smotriomsk.ru/info.htm) требуют активную ссылку при использовании материалов в электронных СМИ или указание авторства в иных случаях; при этом владельцем конкретной камеры указан Zegna Omsk. Эти правила не подтверждают право LiveMap использовать камеру. Тот же iframe на тестовой странице `http://localhost:5173` остался пустым (`about:blank`). Камера сохранена только как неопубликованный кандидат. Требуется разрешение владельца и проверка на домене LiveMap.

Поиск RUTUBE также нашёл эфиры LIVEPOINTS из Омска, Самары и Владивостока. Поскольку канал уже блокирует встраивание других эфиров с `Referer` LiveMap, эти записи не следует публиковать по одной лишь отметке `is_on_air` в поиске; каждую потребуется проверить на конкретном домене. Бесплатный [виджет LiveEarthViewer](https://liveearthviewer.com/embed/cams) встраивает их целую карту камер, а не отдельный эфир в карточке LiveMap, поэтому не заменяет источник для C01.

## Воспроизводимая публикация

1. После миграций выполните `uv run livemap-seed-candidates`: записи появятся как неопубликованные черновики.
2. Пока дата браузерной проверки в реестре моложе семи дней, выполните `uv run livemap-seed-verified`. Команда сверяет данные с проверенным реестром, делает сетевую проверку эфира, публикует только отмеченные источники (Дворцовый мост и две камеры экопарка) и пишет аудит. Новосибирский источник не отмечен для публикации. Повторный запуск не продлевает дату проверки и не возвращает снятую с публикации камеру.
3. Запустите `uv run livemap-worker` для периодического контроля. Для повторного включения после жалобы или истечения проверки администратор должен заново проверить источник и iframe через админ API.

Worker для RUTUBE сверяет наличие публичного live HLS в официальном API с `Referer` сайта LiveMap и не считает один лишь ответ iframe `200` доказательством работающего эфира. Проверка реальных кадров остаётся ручной: сайт плеера может открыть оболочку, даже если видео не воспроизводится.

## Новые опубликованные камеры · 27 сентября 2026

[Экопарк «Долина Нарзанов»](https://dolinanarzanov.ru/new-online) сам показывает две камеры через IPEYE: панораму парка и парковку. Координаты экопарка `[42.67739, 43.69520]` (долгота, широта) взяты с [сайта владельца](https://dolinanarzanov.ru/). [IPEYE описывает выдачу кода плеера для размещения на сайте](https://www.ipeye.ru/translyaciya-video-na-sajt). LiveMap встраивает исходные плееры без перепередачи видео и показывает название владельца и ссылку на его страницу.

Оба iframe 27.09.2026 воспроизведены с `http://localhost:5173` в Chromium: панорама `2560×1440`, парковка `1920×1080`, `readyState=4`, видео не стояло на паузе и его время увеличивалось. Те же параметры подтверждены после запуска плееров в карточке LiveMap. `CameraProbe` повторно подтвердил доступность перед публикацией, а обновлённый worker затем сохранил оба статуса `online`. В БД и API это **одна точка с двумя камерами**; `GET /api/v1/places` вернул маркер с `online_count=2`, детальная карточка вернула два URL воспроизведения. Проверка локального origin не гарантирует работу на будущем публичном домене. Контакт владельца для снятия с публикации: `dolinanarzanov2020@gmail.com`.

Путь IPEYE и параметры iframe разрешены в коде точным шаблоном. Непроверенные параметры и произвольные адреса с query-строкой не становятся доступными через публичный API. Автоматический импорт знает два проверенных идентификатора, страницу владельца и дату проверки; повторный запуск не обновляет её.

## Повторная проверка GitHub и RTSP · 27 сентября 2026

[Live-Environment-Streams](https://github.com/william-ricchiuti/Live-Environment-Streams) содержит [64 записи России](https://github.com/william-ricchiuti/Live-Environment-Streams/blob/main/data/RU.json). Это набор для поиска кандидатов, а не разрешение владельцев камер на показ в LiveMap. В российских записях есть HLS и YouTube, но подходящего одобренного RTSP-источника не найдено. Большинство записей пришло из OpenCCTV; отметки `active` и `last_verified` относятся к проверкам набора и не заменяют текущую проверку нашего сайта.

Из этого набора добавлен **неопубликованный** кандидат: проспект Губернатора Анатолия Гужвина, 10, Астрахань, `https://dvr.astrakhan.ru/guba-10-hd-1/index.m3u8`. 27.09 HTTPS-манифест и [штатный плеер оператора](https://dvr.astrakhan.ru/guba-10-hd-1/embed.html) отвечали `200`; манифест вернул `Access-Control-Allow-Origin: *`, а `CameraProbe` подтвердил его доступность. Последняя успешная проверка в исходном наборе датирована 23.02.2026. Реальные кадры в браузере с LiveMap, владелец, точность координат и право на повторное размещение пока не подтверждены. Страница плеера не содержит условий использования. Камера остаётся скрытой; `permission_evidence_url` и контакт для удаления пусты до проверки у владельца.

Ещё два адреса из того же набора проверены и не добавлены в каталог: HLS площади Ленина в Новосибирске (`wowza-2.novo-sibirsk.ru`) дал `connection_failed`, а HLS площади во Владивостоке (`hls7.vladlink.ru`) не завершил TLS-подключение в отведённое время. Эти результаты относятся к проверке 27.09 и могут измениться.

Ранее присланные [pbkompasz/webcams](https://github.com/pbkompasz/webcams), [CamioCam/rtsp](https://github.com/CamioCam/rtsp) и [примеры rtsp-camera-view](https://github.com/grigory-lobkov/rtsp-camera-view/issues/3) не дают подтверждённую разрешённую камеру России. [iptv-org/iptv](https://github.com/iptv-org/iptv/blob/master/streams/ru.m3u) содержит преимущественно телеканалы, а не привязанные к улицам камеры. Для RTSP принят проектный план [MediaMTX](media-gateway.md): шлюз добавляется вместе с первой одобренной камерой, с отдельным приватным upstream и публичным HLS URL.
