# Стартовые live-источники

Проверка выполнена 26 сентября 2026 года. [Справка RUTUBE](https://rutube.ru/info/embed/) описывает встраивание открытых трансляций через официальный iframe-плеер. Владелец конкретного эфира может ограничить его показ на сторонних сайтах. LiveMap показывает разрешённый плеер без копирования видео и указывает канал в карточке.

HTTP-ответ iframe `200` без блокирующих `X-Frame-Options` и `frame-ancestors` сам по себе не доказывает право показа на конкретном сайте. Эфир Дворцового моста воспроизведён во вложенном плеере локального LiveMap: `readyState=4`, кадр 1280×720, время видео увеличивалось. Это проверка на указанную дату, а не гарантия непрерывной работы или доступности на будущем публичном домене.

Контакт платформы для удаления: `help@rutube.ru`. Право платформы на встраивание не даёт права скачивать, перезаписывать или транслировать видео через собственный сервер. Остальные кандидаты в `demo/camera_candidates.json` остаются скрытыми до отдельного подтверждения условий.

## Поиск второго города · 27 сентября 2026

На [странице городских камер «АльянсТелеком»](https://inetvl.ru/dlya-biznesa/alyansglaz/) опубликованы адреса, координаты и iframe для Владивостока (Золотой мост), Уссурийска (Садовая, 3а) и Находки (Пирогова, 16). Их собственные плееры показали кадры с текущей датой и временем. Камера «Мажерка» в Находке показывала ошибочную дату 1972 года и исключена. Три работающих источника сохранены в реестре и локальной БД **только как неопубликованные кандидаты**.

[Описание услуги оператора](https://inetvl.ru/dlya-biznesa/videonablyudenie/) предлагает владельцам встраивать *свои* камеры. Это не подтверждает право LiveMap встраивать перечисленные камеры. Кроме того, iframe на тестовой странице `http://localhost:5173` остались пустыми, хотя их собственные страницы воспроизводились. Нужно получить разрешение оператора и проверить воспроизведение именно на домене LiveMap до публикации. Даты браузерной проверки для этих кандидатов не записаны в `embed_verified_at`, чтобы автоматический импорт не счёл её подтверждением работоспособности на LiveMap.

Повторная проверка эфиров LIVEPOINTS [Москва-река](https://rutube.ru/live/video/849eda0a248516e770a6172f10a14308/) и [Сочи, канатная дорога](https://rutube.ru/live/video/49324935661e2c9527b171c8370e9995/) дала `http_error` от API RUTUBE с `Referer` LiveMap, как и эфир Новосибирска. Они не подходят для каталога до разрешения владельца. Поэтому C01 остаётся открытой: достоверно опубликован по-прежнему один город.

Дополнительно проверены RUTUBE-эфиры LIVEPOINTS из Москвы (Марксистская), Уфы (Черниковка), Волгограда (вокзал), Астрахани (площадь Ленина) и Ярославля (площадь Ленина): все пять дают `http_error` при запросе официального API с `Referer` LiveMap. Публичная страница или отметка `broadcast` в поиске RUTUBE не снимает ограничение автора на стороннем сайте.

[Live World Webcams](https://liveworldwebcams.com/embed-webcam/) предлагает свободно вставляемый виджет и [показывает 14 камер России](https://liveworldwebcams.com/category/asia/russia/). Однако его [публичный код виджета](https://liveworldwebcams.com/wp-content/plugins/lww-embed-widget/assets/widget.js) выводит миниатюру с переходом `Watch Live` на сайт источника, а не живое видео в карточке. Поэтому виджет не закрывает требование C01 и не добавлен в каталог как live-плеер.

[smotriomsk.ru](https://smotriomsk.ru/cam13.htm) указывает точное место камеры на улице Ленина, 5 и встраивает VK Video. 27.09 на странице проекта после запуска плеера появился текущий кадр 856×480 (`readyState=4`, воспроизведение не приостановлено). [Правила проекта](https://smotriomsk.ru/info.htm) требуют активную ссылку при использовании материалов в электронных СМИ или указание авторства в иных случаях; при этом владельцем конкретной камеры указан Zegna Omsk. Эти правила не подтверждают право LiveMap использовать камеру. Тот же iframe на тестовой странице `http://localhost:5173` остался пустым (`about:blank`). Камера сохранена только как неопубликованный кандидат. Требуется разрешение владельца и проверка на домене LiveMap.

Поиск RUTUBE также нашёл эфиры LIVEPOINTS из Омска, Самары и Владивостока. Поскольку канал уже блокирует встраивание других эфиров с `Referer` LiveMap, эти записи не следует публиковать по одной лишь отметке `is_on_air` в поиске; каждую потребуется проверить на конкретном домене. Бесплатный [виджет LiveEarthViewer](https://liveearthviewer.com/embed/cams) встраивает их целую карту камер, а не отдельный эфир в карточке LiveMap, поэтому не заменяет источник для C01.

## Воспроизводимая публикация

1. После миграций выполните `uv run livemap-seed-candidates`: записи появятся как неопубликованные черновики.
2. Пока дата браузерной проверки в реестре моложе семи дней, выполните `uv run livemap-seed-verified`. Команда сверяет данные с проверенным реестром, делает сетевую проверку эфира, публикует только отмеченный петербургский источник и пишет аудит. Новосибирский источник не отмечен для публикации. Повторный запуск не продлевает дату проверки и не возвращает снятую с публикации камеру.
3. Запустите `uv run livemap-worker` для периодического контроля. Для повторного включения после жалобы или истечения проверки администратор должен заново проверить источник и iframe через админ API.

Worker для RUTUBE сверяет наличие публичного live HLS в официальном API с `Referer` сайта LiveMap и не считает один лишь ответ iframe `200` доказательством работающего эфира. Проверка реальных кадров остаётся ручной: сайт плеера может открыть оболочку, даже если видео не воспроизводится.
