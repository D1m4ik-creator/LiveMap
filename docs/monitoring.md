# Внешний мониторинг LiveMap

Workflow `.github/workflows/monitor.yml` должен находиться в default branch `main`.
Он проверяет readiness БД, непустую карту и свежесть камер раз в шесть часов
(00:17, 06:17, 12:17, 18:17 UTC; 03:17, 09:17, 15:17, 21:17 по Москве).
Изменение файлов мониторинга в main также запускает проверку. Отчёт
`monitor-result.json` сохраняется в GitHub Actions на 14 дней.

Render Free может просыпаться медленно. Предусмотрены три попытки с паузой
30 секунд и HTTP timeout 60 секунд; job ограничен 15 минутами.
Проверка не обеспечивает постоянную работу встроенного worker.

## Доставка оповещений

Для GitHub Issues задайте repository variable `LIVEMAP_MONITOR_ISSUES=true`
после выбора этого канала владельцем. Используется встроенный GITHUB_TOKEN
с разрешением issues:write. Новый сбой открывает один incident, повторные
неизменные сбои не создают сообщения, восстановление закрывает incident.
Сторонние issues и pull requests не изменяются.

До включения переменной отдельный канал доставки не настроен.
Уведомления GitHub Actions зависят от настроек аккаунта владельца.
Для подтверждения доставки нужен реальный запуск и проверка полученного
уведомления; unit-тесты сами по себе этого не подтверждают.

## Проверки

`python -m unittest discover -s tests -p test_public_monitor.py -v`.
Тестируются холодный старт, отказ БД, устаревший worker, пустая карта,
исчерпание сетевых попыток, открытие/закрытие incident и отсутствие дублей.
Скрипт проверяет условия также при `python -O`.

Полное E06 остаётся открытым до подтверждения канала и доставки, а также
подключения внешнего сборщика внутренних Prometheus-метрик, если он нужен
для постоянного сервиса.
