# Внешний мониторинг LiveMap

Workflow `.github/workflows/monitor.yml` находится в default branch `main`.
Он проверяет readiness БД, непустую карту и свежесть камер раз в шесть часов
(00:17, 06:17, 12:17, 18:17 UTC; 03:17, 09:17, 15:17, 21:17 по Москве).
Изменение файлов мониторинга в main также запускает проверку. Отчёт
`monitor-result.json` сохраняется в GitHub Actions на 14 дней и содержит
время ответа readiness, сводки камер и карты, число published/online/stale.
[Запуск из main 03.10.2026](https://github.com/D1m4ik-creator/LiveMap/actions/runs/37130964493)
прошёл после слияния согласованного PR #2.

Render Free может просыпаться медленно. Предусмотрены три попытки с паузой
30 секунд и HTTP timeout 60 секунд; job ограничен 15 минутами.
Проверка не обеспечивает постоянную работу встроенного worker.

## Доставка оповещений

GitHub Issues включён: repository variable `LIVEMAP_MONITOR_ISSUES=true`.
Используется встроенный GITHUB_TOKEN
с разрешением issues:write. Новый сбой открывает один incident, повторные
неизменные сбои не создают сообщения, восстановление закрывает incident.
Сторонние issues и pull requests не изменяются.

Отдельный incident создаётся при сбое копирования; восстановление сервиса
не закрывает сбой backup. [Тестовое оповещение #3](https://github.com/D1m4ik-creator/LiveMap/issues/3)
создано в репозитории и закрыто после проверки. Это подтверждает доставку
в GitHub Issues. Личные email/push зависят от настроек аккаунта владельца;
их получение не подтверждено.

## Проверки

`python -m unittest discover -s tests -p test_public_monitor.py -v`.
Тестируются холодный старт, отказ БД, устаревший worker, пустая карта,
исчерпание сетевых попыток, открытие/закрытие incident и отсутствие дублей.
Скрипт проверяет условия также при `python -O`.

E06 для демостенда завершён. Для постоянного production отдельная E12 требует
процессов без сна, внешнего сборщика внутренних Prometheus-метрик, SLA и
проверки личных уведомлений. Текущие замеры раз в шесть часов не заменяют
непрерывный сбор метрик.
