# Проверка выпуска LiveMap · 2026-09-30

Стенд: https://livemap-demo.onrender.com/. Ветка: `codex/livemap-foundation`.
Это проверка демонстрационного стенда Render Free + Supabase, с указанием
отдельных незавершённых требований постоянного production-сервиса.

## Остановка камер в Chrome / Edge

Пользователь сообщил, что камеры «Интернациональная улица» (#15) и
«Судостроительная улица» (#16) останавливаются после нескольких секунд.
Оба источника отдают обновляемые HLS-манифесты без `ENDLIST`: номера сегментов
увеличиваются; окно воспроизведения примерно 30 секунд. В Chromium на публичном
стенде оба видео непрерывно проигрывались больше трёх минут. Это не исключает
сбой на другом устройстве или соединении.

Плеер теперь начинает у текущего эфира, ограниченно повторяет сетевые загрузки,
восстанавливает остановившийся live-буфер и обнаруживает отсутствие прогресса.
Добавлены кнопка «К прямому эфиру» и пояснение обновляемой шкалы. При закрытии
плеера таймеры, подключения и HLS освобождаются. Пользовательская пауза сохраняется.
Записи с `ENDLIST` / `PLAYLIST-TYPE:VOD` отвергаются backend probe; HLS-плеер
также показывает запись как недоступный live-источник, без зацикливания.

Интеграционный сценарий `frontend/e2e/hls-live.spec.ts` использует настоящие
потоки, проверяет видео дольше одного окна и восстановление после 18-секундного
сетевого обрыва. Запуск внешних источников требует `LIVE_STREAM_E2E=1`.
Chromium и Firefox воспроизводят обе камеры и автоматически восстанавливаются
после обрыва без нажатия кнопки (четыре сценария прошли за 2,6 минуты).
Тестовый WebKit на Windows
не начал декодирование этих потоков (`videoWidth=0`); Safari на устройстве Apple
ещё требует проверки. Проверка Edge отдельным бинарником не выполнялась.

## API, база и администрирование

- 28 backend-тестов прошли: миграции, каталог, bbox, антимеридиан, права,
  импорт, публикация, worker, SSRF, HTTP-границы и отбраковка VOD.
- Для 550 синтетических точек выдача ограничена 500: ответ 90 876 байт;
  медиана bbox 16,44–18,62 мс, максимум 27,29 мс. При 20 параллельных запросах
  максимум 568,44–612,35 мс в двух замерах. Это локальный PostGIS/ASGI,
  без сетевой задержки Render.
- Плотная карта проверена в Chromium на production-сборке: раскрытие кластера
  из 550 мест, показ 500 точек и списка, три быстрых изменения масштаба дают
  два bbox-запроса, ошибок JavaScript нет. За две секунды анимации — 62
  кадра requestAnimationFrame, p95 интервала 50 мс. Измерение headless на этой
  машине с пустой подложкой; оно не доказывает 60 FPS на любом устройстве или
  скорость загрузки внешних тайлов. Сценарий: `frontend/e2e/dense-map.spec.ts`.
- Worker обработал 550 камер за 138 батчей и 7,484 секунды; максимум четыре
  проверки одновременно, все 550 результатов сохранены. Claim/save выполнены
  в настоящем локальном PostGIS, upstream заменён контролируемой проверкой
  длительностью 10 мс. Пропускная способность реальных операторов не измерялась.
- Добавлены индексы четырёх внешних ключей: `admin_sessions.user_id`,
  `audit_events.actor_id`, `camera_reports.camera_id`, `cameras.source_id`.
  Индексы применены к Supabase; миграция `20260930_03` допускает их наличие.
- В облачной базе пройден административный цикл: вход, черновик,
  запрет публикации до одобрения, одобрение источника, публикация,
  сохранение камеры с сохранением сессии, аудит, снятие с карты, выход.
  Временные записи удалены. Сценарий: `scripts/cloud_acceptance.py`.
- Пять пользовательских UI-сценариев запускаются в Chromium, Firefox и
  WebKit. Они используют управляемый каталог и iframe, отдельно от проверки
  настоящих эфиров. Два параллельных browser worker и ожидание интерфейса
  10 секунд устраняют ограничение слишком короткого ожидания WebKit на этой машине.

## Проверка безопасности E05

Независимый review исходного коммита `0a87548` проверил авторизацию, права,
публикацию, SSRF/DNS/перенаправления, iframe, XSS/SQL, CSP/CORS, зависимости,
секреты, Docker/Render и роли базы. Обнаружены два замечания средней тяжести;
оба исправлены в этом выпуске:

1. За Caddy все пользователи могли попадать в один IP-бакет rate limiter.
   Приватный API Compose доверяет forwarded-заголовкам от прокси; публичные
   подключения идут через Caddy. Тест подтверждает разделение доверенных IP
   и игнорирование подмены от недоверенного адреса.
2. JSON мог буферизоваться до проверки размера. ASGI ограничивает login до
   16 КБ, обычные запросы до 64 КБ, импорт до 8,1 МБ, включая chunked body;
   время чтения ограничено 30 секундами. Caddy ограничивает API до 8,1 МБ.

Тесты регрессий проходят; `npm audit` и `pip-audit` не нашли известных
уязвимостей. Supabase Security Advisor не вернул замечаний. Runtime и миграции
используют разные роли, схема приватная, RLS включён, TLS проверяет hostname
и цепочку. Это не гарантия отсутствия неизвестных уязвимостей. Сканирование
привязано к исходному снимку; исправления проверены отдельными регрессиями.
Измерение расхода токенов security scan недоступно.

## Эксплуатация и оставшиеся задачи

- Публичный `/api/v1/health/cameras` сообщает только агрегированные online,
  published, stale и latest_check_at. `scripts/check_public_service.py`
  проверяет БД, свежесть worker и непустую карту, учитывая холодный старт.
- Workflow мониторинга подготовлен. GitHub запускает расписание только из
  default branch: в рабочей ветке оно **ещё не активно**. Канал уведомлений
  и внешний сбор метрик ещё нужно настроить.
- Во время текущих проверок Render показывал 0,0031–0,0046 CPU и
  107–132 МБ RAM для API со встроенным worker. Эти числа относятся к
  каталогу из 15 опубликованных камер, не к нагрузочному каталогу из 550.
- `scripts/cloud_backup.py` передаёт pg_dump сразу в age; незашифрованный
  экспорт не сохраняется. Проверены шифрование, расшифровка, восстановление
  всех таблиц и PostGIS в отдельной локальной базе на синтетических данных.
  Реальный экспорт Supabase через session pooler завершается EOF: валидной
  облачной копии пока нет. Внешнее хранение и расписание остаются E08.
- E03/E10: Safari, другое физическое устройство, звук и измерение задержки.
- E04: измерения плотного набора выполнены в тестовой среде; перед увеличением
  production-каталога повторить их на целевых устройствах и настоящих upstream.
- C01e/C01f/C09: замена трёх неисправных источников, уточнение координат,
  первый согласованный RTSP. E11: ограничения ключа, бюджет и SLA карты.

Render Free засыпает при простое: круглосуточный worker не обеспечен.
Незавершённые пункты сохранены на Kanban-доске.
